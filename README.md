# 人偶姿勢產生器 Figure Poser

拖動圓點擺出姿勢，即時 3D 預覽，一鍵匯出可直接列印的 STL。

純前端、零編譯、零外部連線。放上 GitHub Pages 就能給整班學生使用。

---

## 這是什麼

一個給國小課堂用的 3D 列印小工具。人偶造型是常見的白色基礎人形：頭是球體、身體是圓角方塊、四肢是膠囊。

學生不需要學任何 3D 軟體，只要在正面圖和側面圖上拖動關節圓點，就能擺出想要的動作，右邊即時看到立體結果，滿意後直接下載 STL。

## 功能

- **雙視圖拖拉** — 正面圖管左右張開、側面圖管前後擺動，兩張圖交替調整
- **即時 3D 預覽** — 拖拉的同時更新，可旋轉、縮放
- **八款預設動作** — 舉手抱頭、歡呼、直立、跪坐、蜷曲、仰躺、側躺、大字型
- **重心提示** — 叉叉是重心落點，偏出支撐範圍會變紅，列印前就知道會不會倒
- **列印難度提示** — 三色指示這個姿勢需不需要支撐，並在 2D 圖上用紅色虛線標出是哪一段肢體
- **單一尺寸參數** — 只需設定頭部直徑，其餘部位依比例連動
- **精確尺寸顯示** — 隨時看到目前姿勢的實際外框，不必等切片軟體才知道
- **STL 匯出** — 自動置中並貼齊列印平台，分段數依模型大小自動調整
- **連結分享** — 姿勢與尺寸都寫在網址裡，傳一條連結給對方，打開就是同一個畫面
- **姿勢代碼** — 一段 JSON，貼進其他工具或存檔用

## 使用

### 線上版

推到 GitHub 後開啟 **Settings → Pages**，Source 選 `main` 分支的根目錄，等一分鐘就會有網址。整個專案是靜態檔案，不需要任何建置流程。

### 本機執行

ES 模組不能用 `file://` 直接開啟（瀏覽器的安全限制），需要一個本機伺服器：

```bash
cd figure-poser
python3 -m http.server 8000
# 瀏覽器開 http://localhost:8000
```

VS Code 使用者也可以直接用 Live Server 擴充套件。

### 疑難排解

**畫面一片空白，按鈕和滑桿都沒出現。**
表示 `src/main.js` 沒有載入成功，頁面上會出現紅色提示框說明原因。最常見的兩種情況：

1. **GitHub Pages 少了 `.nojekyll`。** GitHub Pages 預設會跑 Jekyll，而 Jekyll 會過濾掉某些資料夾。
   請確認專案根目錄有一個空白的 `.nojekyll` 檔案——它是隱藏檔，用網頁拖拉上傳時很容易漏掉。
   補的方法：在 repo 頁面按 **Add file → Create new file**，檔名輸入 `.nojekyll`，內容留空後 Commit。
2. **在本機直接雙擊 `index.html`。** ES 模組不能用 `file://` 載入，必須透過本機伺服器，見上一節。

**更新了網站，但看起來完全沒變。**
標題旁邊有版本編號，先看它有沒有跟著變。沒變就是瀏覽器還在用快取——
GitHub Pages 對 JS 檔預設快取十分鐘，按 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd>
（macOS 是 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd>）強制重新載入，或等十分鐘後自然更新。

**手機上 3D 預覽裡的人偶跑到角落。**
v1.10.0 已修正。原因是 `renderer.setSize(w, h, false)` 的第三個參數關掉了 CSS 尺寸更新，
畫布會被放大成容器的 `pixelRatio` 倍再被裁切。若你改動 `viewer3d.js`，請保持 `setSize` 只傳兩個參數。

**3D 預覽區顯示「WebGL 不可用」。**
這台裝置沒有硬體加速或瀏覽器停用了 WebGL。拖拉編輯與 STL 匯出不受影響，可以照常使用。

## 操作說明

### 拖拉

| 控制點 | 作用 |
|---|---|
| 大圓點（手肘、膝蓋） | 決定上臂、大腿的指向 |
| 小圓點（手掌、腳掌） | 決定手肘、膝蓋的彎曲程度 |
| 頭部圓點 | 頭部傾斜（限制在 30 度內） |

藍色是左半邊、橘色是右半邊。**正面圖和側面圖要交替調整**——一張圖只能決定一個方向，兩張都調過才擺得準。

### 滑桿

拖拉做不到的自由度才用滑桿：全身前傾／側傾（決定站、坐、躺、趴）、腰部前彎與扭轉、手臂沿自身軸線的扭轉（做「抱頭」這類動作會用到）。

每根滑桿兩側都有 **−／+** 微調鈕，按一下走一格（角度 1°、頭部直徑 0.2 mm、底座 1 mm），
按住不放約半秒後會開始連續跳。滑鼠拖不到剛好的數字時用它。滑桿本身取得焦點後也可以用方向鍵。

**全身前傾**：正值往前（+90 就是趴著、臉朝下），負值往後（−90 是仰躺、臉朝上）。

各關節的可動範圍依人體實際數據（ROM，取臨床常用區間的寬端）設定：

| 關節 | 範圍 | 人體參考 |
|---|---|---|
| 肩・前後擺 | −60 ~ 180 | 屈曲 180 / 伸展 50~60 |
| 肩・外展 | −40 ~ 180 | 外展 180 / 內收 30~45 |
| 臂・扭轉 | −90 ~ 90 | 肩關節內外旋各約 90 |
| 肘 | 0 ~ 150 | 0 ~ 145 |
| 髖・前後擺 | −30 ~ 130 | 屈曲 120~125 / 伸展 20~30 |
| 髖・外展 | −30 ~ 50 | 外展 45~50 / 內收 20~30 |
| 膝 | 0 ~ 150 | 0 ~ 135~150 |
| 腰・前彎 | −30 ~ 80 | 前彎 80~90 / 後仰 20~30 |
| 腰・扭轉 | −45 ~ 45 | 軀幹旋轉各約 35~45 |
| 頭・傾斜 | 錐角 45 | 頸部前彎 50 / 側彎 45 |

「臂・扭轉」限制在 ±90 有額外理由：它決定手肘往哪一側折，超過 90 就會變成手肘反折。

「全身前傾／側傾」不是人體關節，而是整具人偶在世界中的擺放方向，因此保留完整 360°。

每一項都通過幾何驗證：範圍內髖球與肩球始終埋在軀幹裡、頭傾到 ±45° 仍與軀幹保有 3.99 mm 的交界。

**腰・前彎／扭轉** 的範圍依人體實際可動角度設定。髖關節的位置掛在軀幹座標系上，
所以不論腰怎麼轉，髖球都埋在軀幹裡，不會出現大腿上端跑到體外的情形。

### 版面

三個視圖的高度會隨視窗調整，控制項則排成多欄壓縮成兩列，把垂直空間盡量留給圖。
在 1700 px 寬、1080 p 的螢幕上，人偶顯示大小約為早期版本的 1.8 倍。

寬螢幕（≥900 px）是三欄並排、每欄 52vh；窄螢幕會改成單欄堆疊，這時三張圖若各佔 52vh 會捲不完，
所以高度降到 40vh。

取景刻意固定不隨姿勢縮放——換動作時畫面若忽大忽小，反而不好瞄準控制點。

### 分享

按「複製連結」拿到的網址長這樣：

```
https://你的網址/#p=88,0,-5,0,20,0,...&h=6.2
```

`p` 是二十個關節角度，`h` 是頭部直徑，有加底座時還會多一個 `b`。刻意用人看得懂的格式而不是編碼字串，
出問題時直接看網址就知道哪個值不對。網址列會在停止操作後才更新，避免瀏覽器對頻繁改寫網址的限流。

學生可以把連結傳進班群或貼到 Google 表單，你點開就是他擺的姿勢，不必再複製一長串 JSON。

### 尺寸

只有一根「頭部直徑」滑桿，其餘部位一律依比例連動。**站姿全高約為頭部直徑的 4.9 倍**，所以想印 30 mm 高的成品，頭部直徑設 6.2 mm 左右。

滑桿下限是 4 mm。再小下去最細的部位（頸部與手臂）會只剩約五條擠出線寬，FDM 印出來很容易斷：

| 頭部直徑 | 站姿全高 | 最細處 | 相當於 0.4 mm 噴頭 |
|---|---|---|---|
| 4 mm | 19.7 mm | 2.11 mm | 5.3 條 |
| 6.2 mm | 30.6 mm | 3.27 mm | 8.2 條 |
| 10 mm | 49.4 mm | 5.27 mm | 13.2 條 |

不同姿勢共用同一組比例，整組印出來大小才會一致。

### 列印難度提示

畫面上第二條提示條會估算這個姿勢需要多少支撐，並把該負責的肢體在 2D 圖上畫成紅色虛線。

判準是 FDM 的通則：**底面與水平夾角小於 45°，而且下方是空的，才需要支撐**。程式逐段檢查四肢：

1. 軸線與水平夾角超過 45° 的肢體，底面自己撐得住 → 跳過
2. 剩下的近水平段，沿底面往下打射線，看碰不碰到別的部位或平台
3. 需支撐面積 ≈ 懸空長度 × 直徑 × cos(仰角)

所以「雙手往上舉」不會被判需要支撐，「雙手往旁邊平舉」會；而「手放在頭上」雖然前臂幾乎水平，
但因為壓在頭上、射線打得到實體，也判為免支撐。

門檻隨模型大小平方縮放（面積本身就是面積量），所以換尺寸時判定一致。

敘述刻意保留「**以目前姿態**」這個前提，不寫成絕對結論。實務上常會在切片軟體裡改變擺放方向，
那會得到完全不同的支撐需求；而且這裡算的是「物理上會不會垂」，不是「某套切片軟體會生成幾克支撐」——
後者取決於門檻角度、支撐型式等設定，硬要對齊只會給出錯誤的精確感。

八款預設都調整過，以目前姿態直接列印都不需要支撐（05 趴伏與 07 側躺各有 1～7 mm² 的邊緣值）。

其中「02 雙手歡呼」值得一提：**上臂仰角 = asin(−cos(外展角))**，所以

| 外展角 | 上臂仰角 | 是否自撐 |
|---|---|---|
| 90° | 0° | ✗ |
| 120° | 30° | ✗ |
| 135° | 45° | 臨界 |
| 150° | 60° | ✓ |

舊值用外展 90°（上臂水平的「球門柱」造型），必然需要支撐——那個剪影本身就與免支撐互斥。
改成外展 150° 後上臂仰角 60°、前臂也維持 60°，兩段都過門檻。想要原本的球門柱造型，
把這串貼進網址即可：`#p=0,0,0,0,0,0,0,90,90,90,0,0,0,0,90,90,90,0,0,0&h=6.2`

教學上這是個好題材：45° 規則可觀察、可實驗，學生拖著手臂看指示燈變色，比講解有效。

## 列印建議

**重疊實體是正常的。** 匯出的 STL 裡，各部位是彼此重疊的獨立封閉實體，沒有做布林聯集。Cura、PrusaSlicer、Bambu Studio、Orca 等切片軟體在切片階段會自動聯集，結果與真聯集完全相同。若要上傳到某些線上列印服務，可先用 Windows 內建的 3D Builder 或 Meshmixer 做一次修復。

**姿勢與支撐。** 跪坐、蜷曲、仰躺、趴地這類接觸面大的姿勢最好印，幾乎不需要支撐。舉手站立的手臂內側、大字型的四肢下方會有懸空，需要支撐或直接接受一點瑕疵。

**重心。** 畫面上的叉叉變紅就代表站不住。可以改姿勢，或用「底座直徑」滑桿加一片薄圓盤（厚 1.2 mm，
貼齊列印平台，與人偶最低處自然重疊成一體）。

**分段數。** 匯出品質同時看兩件事：表面誤差，以及一個段數下限（一般 24、精細 40、最高 64）。
只看誤差的話，小模型會算出很少的段數——3 mm 的頭在 0.05 mm 誤差下只有 18 段，幾何上夠精確，
但肉眼與切片軟體的平面著色都看得出稜角。大模型則仍由誤差決定，不會被下限綁住。

以 3 公分成品為例，「一般」的表面誤差已經是 0.027 mm，遠低於 FDM 噴頭的 0.4 mm——
所以稜角只是螢幕上的觀感，實體印不出那個差別。光固化（XY 約 0.035 mm）才值得選「精細」以上。

| 選項 | 6.2 mm 頭的段數 | 三角面 | 檔案 |
|---|---|---|---|
| 一般 | 24 | 10,716 | 0.51 MB |
| 精細 | 40 | 29,212 | 1.39 MB |
| 最高 | 64 | 73,996 | 3.53 MB |

## 專案結構

```
figure-poser/
├─ index.html            版面與樣式
├─ src/
│   ├─ skeleton.js       體型比例、正向運動學、拖曳反解、外框計算
│   ├─ presets.js        八款預設動作
│   ├─ meshes.js         three.js 網格產生
│   ├─ editor2d.js       正面／側面拖拉編輯器
│   ├─ viewer3d.js       3D 預覽場景
│   ├─ stl.js            二進位 STL 匯出
│   └─ main.js           UI 綁定
└─ lib/                  three.js（已打包，不需連外）
```

`skeleton.js` 是全專案唯一的幾何真相來源，2D 編輯器、3D 預覽、STL 匯出都呼叫同一份運動學，不會出現三邊對不起來的情況。

所有長度以「頭半徑 = 1」為單位，實際尺寸只是最外層的一個縮放，因此改變頭部直徑不需要重建任何網格。

## 驗證

改過體型比例或運動學之後，可以跑一次自動測試：

```bash
npm install --no-save three jsdom
node test/verify.mjs
```

41 項檢查，涵蓋：

- **幾何約束** — 用軀幹的有號距離場確認肩球、髖球確實埋在表面內
- **接縫平滑度** — 關節兩側直徑是否相同、圓角是否夠大
- **大腿穿背偵測** — 逐點掃描大腿膠囊，找出從軀幹背面凸出來的部分（就是那塊「屁股」）
- **拖曳反解** — 一萬次隨機往返，確認角度換算可逆
- **STL 正確性** — 解析二進位檔的每個頂點，確認置中、貼齊平台、無退化三角形
- **UI 串接** — 用 jsdom 模擬點按鈕、拉滑桿、拖控制點，含關節角度上下限

## 客製化

### 體型比例的依據

全高只有 **4.94 個頭高**（成人約 7.5），頭與軀幹刻意放大——這是 Q 版風格，也與參考商品一致。
但四肢的分節比例是照成人實測值（Drillis & Contini）設定的：

| 部位 | 佔全高 | 成人實測 | 差異 |
|---|---|---|---|
| 頭高 | 0.203 | 0.130 | +56%（風格） |
| 軀幹長 | 0.358 | 0.288 | +24%（風格） |
| 上臂 | 0.190 | 0.186 | +2% |
| 前臂 | 0.150 | 0.146 | +3% |
| 大腿 | 0.238 | 0.245 | −3% |
| 小腿 | 0.227 | 0.246 | −8% |
| 肩寬 | 0.256 | 0.259 | −1% |

**前臂／上臂 = 0.787**，貼合成人的 0.785。這個比值不受大頭風格影響，是最乾淨的錨點——
早期版本是 0.941（前臂相對長 23%），手看起來會過長。

**改體型比例** — 編輯 `src/skeleton.js` 最上方的 `P` 物件。肩、髖的位置不需要自己算：程式會依軀幹表面自動往內推一個關節半徑，所以改動比例或圓角時，關節不會突然凸出體外。

兩個要注意的地方：

- `torsoR`（軀幹圓角）建議不小於 `armR`，肩部才收得進去；上限是 `min(寬, 厚) / 2 = 0.765`。
  圓角越大，軀幹底部殘留的水平平面越小。這個平面一旦朝正下方又沒被腿遮住（跪坐最容易），
  在切片軟體裡會變成一塊懸空的平板，很容易被誤認成沒取消掉的底座。
  0.60 時該平面有 4.22 mm²、跪坐會露出 1.52 mm²；目前的 0.72 只剩 0.17 mm²；設到 0.765 則完全沒有平面。
- `foreScale` 請維持 1。關節處是兩顆球相接，半徑相同時圓柱與球正好相切，銜接才平滑；一旦不等於 1，較粗的那一端就會出現一圈台階。

**新增預設動作** — 在 `src/presets.js` 加一筆即可，未列出的欄位視為 0。最快的做法是先在畫面上拖出想要的姿勢，複製「姿勢代碼」貼進去。

**改造型風格** — `src/meshes.js` 決定各部位用什麼幾何。想把頭換成別的形狀、或讓四肢有錐度，改這裡。
